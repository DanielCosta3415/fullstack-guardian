# Professional assurance and cooperative results

Dev.4 implements the N01–N18 audit response. Implementation, native loading, narrow development observations and professional qualification are distinct. No role is advertised as universally expert or infallible.

## Contracts and planning

`core/professional-contracts-v1.json` contains all39 professional definitions. Typed capabilities are checked against132 taxonomy entries; routing terms are separate lexical hints. Required/conditional/optional tool needs do not assert availability or grant authority. G01/G02 permit review/exploration rather than implementation; S07 explicitly covers i18n.

The primary assumes A00 and interprets user obligations, context and risks. It can finish simple tasks directly. The router recommends the smallest relevant team; lexical improvements do not prove complete semantic understanding. Applicable phase owners are selected or explicitly not delegated, with reasons pending primary confirmation. Imported plans reconstitute bindings, gates, risk and budget. Every task includes a request obligation marked as a proposal, plus applicable explicit obligations. No plan self-certifies coverage.

Each planned role binds its complete professional contract hash and result fields. A changed mission, method, capability or handoff invalidates old plans even if checkpoints stay the same. Consult `guardian.py route --help` and `guardian_platform.py plan --help` for stage and reviewed intent-file inputs.

## Results and integration

Bounded CLI tasks return a closed12-field professional result: task/agent/version, obligations, artifacts, facts, assumptions, decisions, checks, unknowns, risks and handoff. Producers cannot declare verified status or accept their own handoff. Results cite relative artifacts and real hashes; incomplete obligations remain explicit.

Completion is only produced. The supervisor compares typed output to the actual CLI stream, artifact bytes and approved checks. Claimed checks require matching argv, relative cwd and independently observed outcomes. Missing outputs, changed artifacts, blocked obligations and new material risk prevent verification. Review identities are supplied by the operator, not authenticated SME credentials.

Supervised integration is the default: absence of a workflow never silently selects legacy behavior. Manual mode requires `--mode manual --acknowledge-unverified` plus the exact reviewed patch hash, refuses to relabel a supervised run, and records `NOT_VERIFIED_BY_SUPERVISOR`. Neither path commits, pushes or deploys.

## Evaluation layers

- Static contracts and regression tests verify the control software.
- Native smoke verifies role identity, completion and paired checks. Schema2 seeded failures require the specific expected assertion rather than arbitrary exit1.
- Public development cases evaluate narrow domain reasoning. The typed harness plans39roles with two fresh attempts each; it does not run the103 open SME scenarios.
- Open professional judgments require independent specialist review against actual artifacts. Their definitions are not passed tests.
- Private holdout and calibrated SME evaluation need a separate controlled process. Paired A/B remains subject to the user's isolated-authentication decision.

`test_native_qualification.py` previews without quota. `--run --out NEW_DIRECTORY` uses existing Codex authentication and inherited model, installing core/packs only in a disposable project. Parent/role/trial/spawn/completion/model/final-JSON correlation and postconditions are checked independently. Oracles are outside the child project, but inherited read permissions are not OS isolation. Public cases are not secret holdout. JSON observations remain uncredentialed even when checks pass.

Record revision/profile/model/harness/stack/corpus and repetitions. Preserve wrong answers, quota failures, missing sessions and drift; never edit an oracle merely to accept an answer. Version a genuinely ambiguous case separately. Never attribute a previous SHA's run to the current candidate.

The corpus preflight implements a deliberately bounded JSON Schema subset for these public artifacts: closed objects, required fields, scalar types, arrays and enums. Unsupported assertions, invalid schemas and oracle/type mismatches fail before native execution; this is not a general JSON Schema engine. Boolean values cannot stand in for integers.

Corpus1.0.0 at bd23370 produced78 corroborated native children and71 exact matches;34 of39 cases matched in both trials. Two independent reviews of all39 scenarios found competing interpretations in the five mismatching cases and additional ambiguity in passing cases. Corpus1.1.0 clarifies subject, units, assumptions and required versus observed values prospectively, retaining all original oracle values and103 open SME designs. Historical failures stay recorded. New runs against this calibrated public corpus are development regressions, not independent holdout evidence or proof of universal professional competence.

## Cooperation and scope

The principal maps the final delivery to requirements, validates handoffs and resolves disagreement with evidence. Shared writes remain serialized; independent read work can parallelize within real limits. Unknown tools/isolation block dependent work while independent authorized tasks continue. Skills and context are loaded by need rather than all at once.

These controls cannot establish expertise across every IT/STEM field or guarantee future-client/production behavior. Qualification must stay scoped to measured work and be invalidated on material changes. More profiles and higher model effort alone are not quality evidence.
