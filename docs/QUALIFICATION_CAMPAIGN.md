# Bounded professional qualification campaign

This campaign advances five separate obligations: real-stack checks, cooperation
under faults, role-specific transfer and repetition, independent review, and
integration/global rollout. None can be inferred from another. In particular,
passing trusted fixture implementations is not an agent performance result.

## Evidence layers

| Layer | Required observations | Does not establish |
|---|---|---|
| Native smoke | Actual role, parent, completion and specified fixture outcomes | Professional competence across a domain |
| Transfer | Fresh role children, varied inputs, host-only expectations, exact schemas and all attempts | Private holdout validity or real framework execution |
| Real stack | Actual engine/browser, fixed trusted fixtures, positive and specifically rejected faulty controls | Ability of every agent to solve arbitrary projects |
| Team acceptance | Distinct producers/consumers, fixed obligations and fresh checks; omission, stale/replayed evidence and revocation challenges | Authenticated identity or enforced OS isolation |
| Release and rollout | Exact-revision CI, provenance, appropriate G01/G02 reviews, recovery and preserved user files | Universal professional certification |

Use `docs/audit-role-remediation.json` for the 67 original item IDs and their
exact acceptance scopes. A new observation closes an item only when it covers
the entire stated criterion, uses the actual required environment, and receives
distinct review. Partial improvements remain partial. Do not promote all 63
outstanding criteria merely because all 39 roles returned a valid response.

## Available evaluation entrypoints

- `tools/guardian_service_checks.py`: opt-in trusted SQLite, loopback HTTP and
  cryptographic fixture checks. Read `docs/SERVICE_CHECKS.md` for exact scope.
- `tools/guardian_browser_checks.py`: opt-in fresh real-browser fixture checks;
  read `docs/BROWSER_CHECKS.md`. Synthetic composition events are not a real OS
  IME run, and DOM/keyboard observations are not screen-reader observations.
- `tools/guardian_transfer_cases.py` and `tools/test_native_transfer.py`: varied
  public transfer cases, fresh native repetitions and role-level observations;
  read `docs/TRANSFER_EVALUATION.md` before opting into model/quota consumption.
- Existing `tools/test_native_agents.py`, `tools/guardian_handoff.py` and
  `tools/guardian_coordination.py`: native smoke, explicit consumer acceptance,
  evidence revocation, bounded team recommendations and scheduling.

Each runner defaults to preview where provided. An explicit execution switch
authorizes only its documented fixed local scope. Candidate outputs stay data;
no artifact may add executable commands, privileges, tool access or destinations.
Network permission failures, missing dependencies, crashes and timeouts cannot
count as successful detection of a seeded defect. Preserve those failed runs.

## Repetition and independence

Fix the case inventory, repetitions, seed and acceptance rule before executing.
Do not rerun only failed cases to report a favorable batch. Separate observed
errors, missing results, inconclusive checks and structural parsing failures.
Keep per-role numerators and denominators, not only an aggregate percentage.
Small samples have wide uncertainty intervals even when every sample succeeds.
Repetitions on the same model and cases do not prove broad independence.

A public seeded generator is not a private holdout. Independent AI review is
useful corroboration, not external accreditation or a human expert baseline.
No comparative worldwide ranking follows without a suitable matched benchmark.
The campaign preserves the user's model/effort and ordinary authentication; no
account, credential, model or reasoning change may be used to evade a limit.

## Rollout boundary

The operator selected the existing `operator-autonomous` release policy. This
permits distinct bounded G01/G02 AI reviews and corroborated local native runs
instead of human review and a dedicated remote Codex machine. It preserves CI,
artifact integrity/provenance, recovery, sandbox and truthful reporting.

Global installation is a separate operation: perform a current dry-run, preserve
unowned configuration/profile bytes, retain rollback material, apply only the
authorized managed update, then execute doctor and actual global/native checks.
Never label a project-installed run as validation of the global installation.
Report the exact revision, installed profiles, optional pack state, evidence
scope and remaining unverified obligations after rollout.

Campaign reports and mutable observations belong in project-local ignored state
or an explicit local output directory. Do not commit raw native sessions,
authentication files, personal prompts or account identifiers to the package.
